## C4 — wire Z3 into `--verify-bodies` ✅ done (`984ca4ac`)

**Shipped.** An `Undecided` path now goes to the solver as `facts ∧ ¬post`:
`Unsat` ⇒ proven, `Sat` ⇒ refuted only when the result is fully determined,
`Unknown`/no solver ⇒ unproven exactly as before. Two prerequisites turned out
to be part of the item: `prove_smt*` invoked `z3` on PATH only while
`is_z3_available` also accepted the managed install dir (so a managed-only
install reported a solver no query could reach), and `/`/`%` fell through the
encoder to `(= l r)` (silently asserting equality) — both fixed. Verified:
36 tests green; `range_bound_does_not_pin` flips 0 → 1 proven once a solver is
present; `--verify-report` on the prelude gives `violated: []`, exit 0.

**Consequence for this roadmap:** C3 (inter-procedural facts) is the only
prover-depth item left, and the parameter-dependent refutations that stay
advisory are the natural seed for its summary work.

**Why it was first.** It is the smallest change with the largest honesty gain:
today a hard goal is reported `Unproven` and only warns. With a solver it
becomes *decided* — proven or refuted with a model. It also fixes the one place
where Counsel must trust a "maybe".

**Design (reuses existing machinery — no new solver surface):**

1. Thread contract params. `verify_one` currently takes `(pre, post, body)`;
   take `params: &[(String, Type)]` from `Definition.parameters` /
   `Transaction.parameters` (the shapes `build_contract_query` expects).
2. On `ProofVerdict::Undecided` for a path, build a **verification condition**
   from that path's facts:
   - `path.state.path_constraints` is already `Vec<Expr>` (precondition + each
     guard with its polarity) — no new collection code.
   - Compose `vc = Or(Not(facts), post)` (or `Implies` if that kind exists).
   - `build_contract_query(&vc, params)` already emits
     `(assert (not <vc>))`, i.e. exactly `facts ∧ ¬post`.
3. Map the answer: `SmtResult::Unsat` → **Proven** (facts imply post);
   `Sat(model)` → **Violated**, quoting the model in the reason;
   `Unknown` / no solver → **Unproven** as today.
4. Gate on `is_z3_available()` so a machine without Z3 behaves *identically*
   to today — this keeps the existing 34 tests and the whole suite green.

**Acceptance**
- A goal the symbolic pass cannot decide (e.g. `[a >= 0][term >= 0] { term a * a; }`)
  reports **proven** with Z3 and **unproven** without it — same source, two
  verdicts, both correct.
- A genuinely false body still reports **violated** with a concrete model.
- `cargo test --lib verify` adds solver-gated tests that **skip** when Z3 is
  absent (the `derive::verify_smt` suite already uses this pattern).
- `brievc freshness` says `fresh` before any timing/verdict claim.

**Risk.** QF_BV non-linear goals (multiplication) can time out; keep the
existing timeout (1000 ms) and map timeout → `Unknown` → `Unproven`, never to
a pass.

## C2 — packaging so `cargo add counsel` works for a stranger ✅ done

**Why it mattered.** A user had to build `brievc` locally — the last barrier
between "works on the author's machine" and "adoptable".

**Options**

| Option | Cost | Verdict |
|---|---|---|
| (a) `build.rs` downloads a **pinned prebuilt `brievc`** tarball from GitHub releases, sha256-verified, cached | small | **chosen — shipped** |
| (b) publish `briev-compiler` to crates.io, compile at build time | large (LLVM toolchain for every user) | reject |

**Resolution order in `build.rs`**: `COUNSEL_BRIEVC`/`BRIEVC` → pinned release
cache → `brievc` on `PATH` → download the pinned, sha256-verified tarball. A
missing compiler is a hard error listing every option — never a silent fallback
to a stale binary (that detour already cost a session; C6 exists for this).
`COUNSEL_NO_DOWNLOAD=1` forbids fetching; `DOCS_RS` skips the native half so docs
still build offline.

**Acceptance — verified**
- Fresh cache, no `BRIEVC`, no `brievc` on PATH: downloads, verifies, extracts and builds (3.9 s).
- Warm cache with a dead proxy: builds in 3.2 s (no network touched).
- `BRIEVC=/path/to/local/brievc` still overrides (dev loop unchanged, 3.2 s).
- No compiler and no network: one message naming all four options.
- The relocatability gate (`6530736`) is untouched — the bundle keeps
  `<prefix>/bin/brievc` + `<prefix>/share/briev/`, which the compiler resolves
  from its own executable, so no `BRIEV_HOME` plumbing is needed.

## C3 — inter-procedural facts (deepest; last)

**The hole.** `expr_supported` (~`verify_bodies.rs:722`) rejects `Expr::Call`
outright, so **any** body that calls a helper is skipped wholesale by
`body_supported`. In practice that is most non-trivial code.

**Design**
1. Build a **summary** per pure-integer `defn`: a value form
   `term == <expr over params>` when the body is single-path and supported
   (e.g. `[a >= 0][term == a + 1] { term a + 1; }` → `f(a) ↦ a + 1`).
2. Substitute at call sites: `Expr::Call(name, args)` with a summary and
   supported `args` becomes the substituted expression; the callee's precondition
   becomes an additional path fact.
3. Order by `analysis/call_graph.rs`; **cycles are refused** (marked
   unsupported) rather than fixed-pointed — conservative and sound.
4. Anything without a summary keeps today's behaviour: the body is skipped.

**Acceptance**
- A two-function program where the caller's post depends on the callee's result
  proves; removing the callee's postcondition drops it back to `unproven`.
- No change to any currently-proven or currently-violated declaration.
